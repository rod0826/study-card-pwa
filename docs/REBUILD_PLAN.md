# JianStudy 재구축 계획

작성일: 2026-08-22
현황 갱신: 2026-09-03

> 이 문서는 재구축 당시의 설계 기록이다. 현재는 시험·과목 카탈로그, 과목 다중 선택, 진행도 v2 이전, 복습 범위, 학습 순서, 결과 화면, v2 카드 데이터와 콘텐츠 해시 기반 PWA 캐시까지 구현했다. 단원 필터, 진행도 내보내기·가져오기, 코드 모듈 분리와 자동 테스트는 후속 작업으로 남아 있다.

## 1. 재구축 목표

JianStudy를 한 번의 시험을 위한 카드 모음이 아니라, 아래 다섯 시험을 계속 누적해 쓰는 개인 학습 앱으로 바꾼다.

1. 중학교 2학년 2학기 중간고사
2. 중학교 2학년 2학기 기말고사
3. 중학교 3학년 1학기 중간고사
4. 중학교 3학년 1학기 기말고사
5. 중학교 3학년 2학기 통합

각 시험에는 실제로 응시하는 과목만 등록한다. 학생은 먼저 시험을 고르고, 그 시험에서 공부할 과목을 하나 이상 선택한 뒤 학습을 시작한다. 과목이나 시험이 추가되어도 화면 코드와 서비스 워커를 매번 직접 고치지 않는 구조를 목표로 한다.

## 2. 현재 프로젝트 판단

### 유지할 부분

- 정적 PWA와 GitHub Pages 배포 방식
- 오프라인 학습
- 원본 PDF·사진과 공개 카드 JSON의 분리
- 전체/취약/오답/새 카드 복습 모드
- 단원 필터, 힌트, 정답 확인, 자기 채점
- 틀림·헷갈림 카드를 뒤에 다시 넣는 학습 방식
- 카드별 안정적인 ID와 브라우저 로컬 진행도 저장

### 재설계할 부분

- 현재 `sets.json`은 시험, 학년, 학기, 과목을 문자열 한 덩어리로 취급한다.
- 화면이 단일 세트 드롭다운이어서 시험별 과목 구성을 보여 주기 어렵다.
- 진행도가 세트별 최신 판정만 저장되어 시험 전체·과목별 학습 현황을 계산하기 어렵다.
- 새 카드 파일을 추가할 때마다 `sw.js`의 파일 목록과 캐시 이름을 손으로 바꿔야 한다.
- `app.js` 한 파일에 데이터, 저장, 학습 큐, 화면 처리가 모두 들어 있다.
- 데이터 형식을 자동 검증하는 스키마와 테스트가 없다.
- `README.md`의 카드 수가 실제 데이터와 맞지 않아 문서가 이미 낡았다.

## 3. 핵심 도메인 구조

시험, 과목, 카드 세트를 서로 분리한다.

```text
Exam(시험)
  └─ ExamSubject(그 시험에서 응시하는 과목)
       └─ CardSet(교과 범위/단원 카드 묶음)
            └─ Card(개별 문제)
```

- `Exam`: 학년, 학기, 시험 종류, 표시 순서, 활성 상태를 관리한다.
- `Subject`: 국어·영어·수학·과학·역사처럼 과목 자체의 정보를 관리한다.
- `ExamSubject`: 특정 시험에 어떤 과목을 치르는지 연결한다. 시험 범위와 준비 상태도 여기에 둔다.
- `CardSet`: 한 시험의 한 과목에 속하는 카드 파일이다. 자료가 많으면 과목 안에 여러 세트를 둘 수 있다.
- `Card`: 문제, 정답, 허용 답안, 힌트, 단원, 출처 식별자를 가진다.

시험 ID는 사람이 읽을 수 있고 연도가 바뀌어도 충돌하지 않게 작성한다.

```text
2026-mid2-sem2-midterm
2026-mid2-sem2-final
2027-mid3-sem1-midterm
2027-mid3-sem1-final
2027-mid3-sem2-integrated
```

현재 `중2-1 기말` 세 과목은 목표 다섯 시험에 억지로 섞지 않고 `2026-mid2-sem1-final`이라는 이전 시험으로 보존한다.

### 과목 목록: `data/catalog/subjects.json`

```json
[
  { "id": "korean", "name": "국어", "color": "coral", "order": 10 },
  { "id": "english", "name": "영어", "color": "blue", "order": 20 },
  { "id": "math", "name": "수학", "color": "green", "order": 30 },
  { "id": "science", "name": "과학", "color": "purple", "order": 40 }
]
```

### 시험별 과목 정보: `data/exams/<exam-id>/index.json`

```json
{
  "examId": "2026-mid2-sem2-midterm",
  "subjects": [
    {
      "subjectId": "korean",
      "enabled": true,
      "scope": "학교에서 확정한 시험 범위",
      "status": "ready",
      "setFiles": ["data/exams/2026-mid2-sem2-midterm/korean/core.json"]
    }
  ]
}
```

`status`는 `empty`, `draft`, `ready`, `reviewed` 중 하나로 제한한다. 카드가 없는 과목은 선택 화면에 준비 중으로 표시하고 학습 시작 대상에서는 제외한다.

### 카드 파일

```json
{
  "schemaVersion": 2,
  "id": "2026-mid2-sem2-midterm-history-core",
  "examId": "2026-mid2-sem2-midterm",
  "subjectId": "history",
  "title": "역사 핵심 암기",
  "sourceRefs": ["history-note-01"],
  "categories": [
    { "id": "unit-01", "name": "단원명", "order": 10 }
  ],
  "cards": [
    {
      "id": "history-unit01-001",
      "type": "blank",
      "categoryId": "unit-01",
      "front": "질문 ___",
      "answer": "정답",
      "acceptedAnswers": [],
      "hint": "힌트",
      "sourceRef": "history-note-01:p3"
    }
  ]
}
```

공개 JSON에는 원본 파일 경로 대신 익명화된 `sourceRef`만 기록한다. 원본과 `sourceRef`의 대응표는 공개 저장소 밖 `source-materials/catalog.local.json`에 둔다.

## 5. 화면과 사용 흐름

### 홈

- 가장 가까운 시험을 첫 카드로 표시한다.
- 다섯 시험을 학년·학기 순으로 보여 준다.
- 각 시험 카드에는 준비된 과목 수, 전체 카드 수, 최근 학습일, 완료율을 표시한다.
- 지나간 시험은 접을 수 있는 `이전 시험` 영역으로 보낸다.

### 시험 준비 화면

- 해당 시험에서 치르는 과목만 체크박스 카드로 보여 준다.
- `전체 선택`과 개별 선택을 모두 지원한다.
- 선택한 과목 수와 학습할 카드 수를 시작 전에 보여 준다.
- 브라우저에 시험별 마지막 과목 선택을 저장해 다음 방문 때 복원한다.
- 준비 중이거나 카드가 없는 과목은 이유와 함께 비활성화한다.

### 학습 설정

- 선택 과목: 한 과목 또는 여러 과목 섞기
- 복습 범위: 전체 / 새 카드 / 취약 / 오답
- 단원: 모든 단원 또는 특정 단원
- 순서: 섞기 / 교과서 순서
- 여러 과목을 선택하면 카드에 과목 배지를 항상 표시한다.

### 카드 학습과 결과

- 기존 힌트, 정답 확인, 맞음/헷갈림/틀림 흐름은 유지한다.
- 학습 종료 시 과목별 결과와 다시 볼 카드 수를 보여 준다.
- `틀린 카드만 다시`, `헷갈림 포함 다시`, `시험 화면으로`를 제공한다.
- 시험 전체 화면에서는 과목별 최근 상태를 집계한다.

## 6. 진행도 저장 구조

저장 키를 버전이 있는 단일 저장소로 바꾼다.

```text
jianstudy:progress:v2
jianstudy:preferences:v1
```

진행도에는 다음을 저장한다.

- 카드별 최근 판정, 총 복습 횟수, 최근 학습 시각
- 카드별 맞음/헷갈림/틀림 누적 횟수
- 시험별 마지막 선택 과목
- 마지막으로 연 시험과 학습 설정

카드의 정답 문구만 고친 경우 진행도를 유지하고, 학습 의미가 달라진 카드는 새 카드 ID를 부여한다. 기존 `study-card-progress:<setId>` 데이터는 최초 실행 때 v2로 한 번만 복사한 뒤 마이그레이션 완료 표시를 남긴다.

진행도는 개인 기기에만 저장하되, 장기 사용을 위해 2단계에서 JSON 내보내기/가져오기를 추가한다. 계정이나 서버 동기화는 현재 범위에 넣지 않는다.

## 7. 권장 코드 구조

빌드 도구나 프레임워크는 당장 도입하지 않고, GitHub Pages에 그대로 배포되는 ES 모듈 기반 정적 PWA로 정리한다.

```text
study-card-pwa/
├── index.html
├── manifest.webmanifest
├── sw.js
├── assets/
├── src/
│   ├── main.js
│   ├── data/catalog-repository.js
│   ├── domain/study-queue.js
│   ├── domain/progress-summary.js
│   ├── storage/progress-store.js
│   ├── storage/migrations.js
│   ├── ui/home-view.js
│   ├── ui/exam-view.js
│   ├── ui/study-view.js
│   └── ui/result-view.js
├── data/
│   ├── catalog/exams.json
│   ├── catalog/subjects.json
│   ├── exams/<exam-id>/index.json
│   └── exams/<exam-id>/<subject-id>/*.json
├── scripts/
│   ├── validate-data.mjs
│   └── generate-asset-manifest.mjs
├── tests/
│   ├── study-queue.test.mjs
│   ├── progress-summary.test.mjs
│   └── data-validation.test.mjs
└── docs/
```

서비스 워커는 카드 파일을 코드에 손으로 나열하지 않는다. 검증 스크립트가 데이터에서 `asset-manifest.json`을 생성하고, 서비스 워커가 이를 기준으로 캐시한다. 앱 셸은 우선 캐시하고 카드 데이터는 사용 시 캐시하는 방식을 권장한다. 이렇게 하면 과목이 많아져도 첫 설치가 지나치게 무거워지지 않는다.

## 8. 재구축 순서

### 0단계: 기준선 고정

- 현재 `4f32aaf`를 복원 기준으로 기록한다.
- 기존 앱의 세 세트와 총 358장을 검증한다.
- 원본 PDF는 저장소 밖에 유지하고 백업 위치를 문서화한다.
- 현재 앱을 재구축 중에도 확인할 수 있도록 태그 또는 보존 브랜치를 만든다.

완료 기준: 기존 앱이 로컬에서 열리고, 세 JSON의 문법·카드 수·ID 중복 검사가 통과한다.

### 1단계: 데이터 기반 만들기

- 시험/과목 카탈로그와 v2 카드 스키마를 만든다.
- 다섯 목표 시험에 국어·영어·수학·과학을 공통 기본 과목으로 연결한다.
- 기말·통합 시험의 추가 과목은 확정되는 시점에 데이터로만 추가한다.
- 기존 중2-1 기말 세트를 v2 데이터로 변환하고 이전 시험으로 등록한다.
- 데이터 검증 및 자산 목록 생성 스크립트를 만든다.

완료 기준: 잘못된 시험 ID, 과목 ID, 카드 수, 단원 참조, 중복 카드 ID, 존재하지 않는 파일을 자동으로 실패 처리한다.

### 2단계: 새 탐색 화면

- 홈의 시험 목록과 시험 상세의 과목 다중 선택을 구현한다.
- 준비 상태와 카드 수를 표시한다.
- 선택한 시험·과목을 새로고침 후에도 복원한다.

완료 기준: 다섯 시험 사이를 이동할 수 있고, 시험마다 서로 다른 과목 선택이 독립적으로 유지된다.

### 3단계: 학습 엔진 분리

- 기존 학습 큐 로직을 DOM에서 분리한다.
- 여러 과목 혼합 학습과 과목/단원 필터를 지원한다.
- 기존 재출제 간격을 테스트 가능한 규칙으로 옮긴다.
- 학습 결과 화면을 추가한다.

완료 기준: 전체/새 카드/취약/오답, 섞기/순서, 단일/복수 과목 조합이 자동 테스트와 모바일 수동 테스트를 통과한다.

### 4단계: 진행도 v2와 이전

- 진행도 저장소와 기존 localStorage 마이그레이션을 구현한다.
- 시험·과목별 집계를 구현한다.
- 내보내기/가져오기와 범위를 명확히 한 초기화를 추가한다.

완료 기준: 기존 기록이 유실되지 않고, 카드/과목/시험 단위 초기화가 서로의 범위를 침범하지 않는다.

### 5단계: PWA·접근성·배포 검증

- 동적 자산 매니페스트와 오프라인 전략을 적용한다.
- 키보드 조작, 포커스, 색상 외 상태 표현, 모바일 safe area를 점검한다.
- GitHub Pages의 하위 경로에서도 모든 URL이 동작하는지 확인한다.
- README와 과목 추가 가이드를 새 구조에 맞춘다.

완료 기준: 최초 온라인 방문 뒤 선택한 시험 자료를 오프라인에서 학습할 수 있고, 새 배포가 이전 캐시에 막히지 않는다.

### 6단계: 시험별 콘텐츠 입력 반복

시험마다 다음 순서로 진행한다.

1. 기본 네 과목의 시험 범위를 확인하고, 기말·통합 시험은 추가 과목도 확인한다.
2. 원본 PDF·사진을 비공개 자료 폴더에 넣고 출처 ID를 등록한다.
3. 원본에서 확인되는 내용만 카드화한다.
4. 보호자가 내용과 범위를 검수한다.
5. `draft`를 `ready`, 검수 후 `reviewed`로 바꾼다.
6. 데이터 검사 후 배포한다.
